# SORGENTE DEI PARAMETRI: training_cfg.yaml
#   Tutti i parametri di rete e simulazione vivono in
#   "Trajectory Generator\baseline_MLP\training_cfg.yaml". Il comando default
#   non richiede flag: output-dir e nome run vengono generati automaticamente;
#   eventuali flag CLI espliciti restano override del YAML. Il training scrive la config RISOLTA
#   (YAML + override CLI) in <output-dir>\training_cfg.resolved.yaml.
#
# REGOLE D'ORO
#  1. Usare SEMPRE "conda run --no-capture-output": senza, conda bufferizza
#     stdout/stderr fino a fine processo e barra live/log NON appaiono.
#  2. Precedenza: il YAML da' i DEFAULT; un flag CLI esplicito VINCE sul YAML.
#     Per una config alternativa (es. macOS) usare --config <file.yaml>.
#  3. Rollout = AUTO-MATCH: senza flag, rollout_eval.py usa l'ultimo training
#     valido in runs\training, prende rl_module_best e carica da solo
#     <run>\training_cfg.resolved.yaml, quindi env/rete/reward/action_mode
#     combaciano col training SENZA ri-specificare i flag. --checkpoint resta
#     override esplicito; --no-auto-config per disattivare; --config <file> per
#     forzare un file. Checkpoint LEGACY senza snapshot -> passare i flag a mano
#     (vedi nota in B).
#  4. Path relativi:
#     - train_ppo_mlp.py salva sotto "Trajectory Generator\runs\training";
#     - rollout_eval.py e imitation_oracle_rollout.py salvano sotto
#       "Trajectory Generator\runs\rollout";
#     - checkpoint/resume storici "runs\nome_run\..." vengono cercati anche in
#       "runs\training\nome_run\...".
#  5. Nome training default: MLP_[strategy]_training_[MM-DD-YYYY], dove strategy
#     deriva da reward.reward_mode (imitation oppure ExNovo). Nome rollout
#     default: stesso nome del training con "rollout" al posto di "training"
#     (oppure _rollout per run legacy). --name aggiunge un suffisso custom;
#     collisioni giornaliere diventano _02, _03, ...
#  6. Rete: definita come num_hidden_layers x dim_hidden_layers (larghezza
#     uniforme) -> fcnet_hiddens = [dim]*num. Override CLI:
#     --num-hidden-layers / --dim-hidden-layers / --fcnet-activation.
#  7. action_mode "absolute" (traiettoria ex-novo + gait clock del lato sano) e'
#     l'unica modalita' di produzione e NON e' nel YAML; "delta"/"raw" restano
#     solo come flag CLI diagnostici (--action-mode). I checkpoint "delta"
#     pre-2026-06-09 sono INCOMPATIBILI.
#  8. Barra live: singola riga in place su TTY; su output rediretto degrada a
#     righe ASCII periodiche (mai mojibake). Debug: --verbose-workers (training)
#     / --verbose (inference).
#  9. Asymmetric actor-critic (ex "critic privileged"): --asymmetric-actor-critic
#     (alias deprecato: --critic-privileged-observation). L'env emette l'obs
#     completa [attore | privilegiato]; il custom RLModule instrada obs[:n_actor]
#     alla policy e il vettore pieno al value head. Rete/obs diverse dal symmetric
#     -> checkpoint NON intercambiabili. In rollout e' auto-impostato dallo snapshot.
#
# Razionali e dettagli (anti-stallo, restart da checkpoint, timeout): README.md.
